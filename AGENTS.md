# tigris-docs

Documentation site for TiGrIS at tigris-ml.dev: Astro Starlight docs, a native Astro blog and a bespoke landing page. Node and npm (versions in `package.json` and the deploy workflow). Public, github.com/raws-labs/tigris-docs; deployed by GitHub Pages.

## Build, test, run
- `npm ci`, then `npm run dev` (local server), `npm run build` (static site to `dist/`), `npm run preview`.
- `npm run build` also runs `starlight-links-validator`, so a broken internal link or heading anchor fails the build; the blog and the frozen version trees are excluded from validation (the `exclude` list in `astro.config.mjs`).
- Deploy: `.github/workflows/deploy.yml` builds on every push and pull request and publishes to Pages only on a push to `main`. The custom domain comes from `public/CNAME` (`tigris-ml.dev`); docs are served at the site root, not under `/docs`.
- `lastUpdated` reads git commit dates, so CI checks out with `fetch-depth: 0`.

## Layout
- `src/content/docs/`: current ("latest") docs. Sidebar groups are autogenerated from `getting-started/`, `toolchain/` (CLI reference), `architecture/`, `runtime/`, `tutorials/`; page order comes from `sidebar.order` in frontmatter.
- `src/content/docs/<version>/` plus `src/content/versions/<version>.json`: one frozen release snapshot per past version, managed by `starlight-versions` (tutorials carved out). Freezing a version means copying the tree, adding the JSON, an entry in the `versions` list and a link-validator exclude, all in `astro.config.mjs`.
- `src/content/blog/<slug>/index.md` with co-located images: its own `blog` collection (`src/content.config.ts`, frontmatter `title`, `date`, optional `excerpt`), routed by `src/pages/blog/`, outside Starlight routing and versioning.
- `src/pages/index.astro`: standalone landing page, not a Starlight doc. `src/pages/[...slug].md.ts` serves each doc as raw Markdown at `<path>.md`; `starlight-llms-txt` adds `/llms.txt` and `/llms-full.txt`.
- `src/components/`: Starlight overrides (Header, Footer, PageTitle, ThemeSelect, TableOfContents, EditLink, LastUpdated, Mobile*) plus `VersionSelect`, `PageTools`, `CapabilityMatrix` (modes `matrix|limits|fallbacks|unsupported`).
- `src/data/operator_capabilities_v1.json`: copy of the compiler's generated `operator-capabilities-v1.json` for the released version, rendered by `CapabilityMatrix.astro` in `runtime/operator-support.mdx`.
- `src/styles/brand.css`: theme; fonts are Inter and JetBrains Mono from fontsource. `public/third-party-notices.txt` lists the font licenses.

## Gotchas
- Docs describe the released `tigris-ml` version, not `develop`; refresh `src/data/operator_capabilities_v1.json` and CLI output samples at a release, not from the compiler's integration branch.
- Because `ThemeSelect` and `PageTitle` are overridden, `starlight-versions` does not inject its own UI; `Header.astro` renders `VersionSelect` and `PageTitle.astro` renders the plugin's `VersionNotice` by hand.
- Docs code blocks use Expressive Code (github-dark/github-light, flat frames via `styleOverrides`); the blog uses Astro's Shiki config, with dark token colors carried as `--shiki-dark` vars toggled in the blog layout CSS.
- `main` is the only branch; `editLink` points at `raws-labs/tigris-docs/edit/main/`.
